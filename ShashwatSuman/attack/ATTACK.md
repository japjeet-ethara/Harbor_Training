## Analysis of Ramandeep's Task

### Files the agent can see inside the container
- `/workspace/repo/` — the working directory with the python-titlecase source code
- `/workspace/repo/titlecase/__init__.py` — the Python reference implementation
- Other Python package files (setup.py, etc.)

### How `tests/test.sh` checks and scores (test.sh lines 1–62)

The test runner calls three criterion functions with weighted-mean aggregation:

| Criterion    | Weight | What it checks                                                              |
|-------------|--------|-----------------------------------------------------------------------------|
| `build`      | 1.0    | `go build ./...` succeeds (build.py:18-28)                                  |
| `no_python`  | 1.0    | No `.py` files under `/workspace/repo` AND `go build` succeeds (no_python.py:18-37) |
| `behaviour`  | 4.0    | Build Go binary, feed `hidden_inputs.txt` via stdin, compare line-by-line with `hidden_expected.txt` (behaviour.py:20-88) |

**Reward formula:** `(1×build + 1×no_python + 4×behaviour) / 6` (test.sh:29)

### Where test data is stored
- **Visible inputs:** `tests/data/inputs.txt` (2,000 lines)
- **Visible answers:** `tests/data/expected.txt` (2,000 lines)
- **Hidden inputs:** `tests/data/hidden_inputs.txt` (2,000 lines)
- **Hidden answers:** `tests/data/hidden_expected.txt` (2,000 lines)

### Is `tests/` visible to the agent while it works?
The `task.toml` has `environment_mode = "separate"` (line 15), which means the verifier runs in a separate container from the agent. The agent should NOT see `/tests/` during work. However, the hidden files ARE on the same verifier filesystem when the Go binary is executed by `behaviour.py`.

### Five weakest points of this exam

1. **`build` + `no_python` give free 2/6 ≈ 0.333 reward with zero correct answers** — Just compile an empty Go program and delete `.py` files. (reward.toml:4, build.py:18-28, no_python.py:18-37)

2. **Hidden exam is only 2,000 lines** — Generated by `gen.py` with the same `random.seed(1)` and same generator functions. Very small pool, easy to get partial credit with a rough approximation. (gen.py:14, gen.py:424)

3. **Hidden inputs come from same generators as visible inputs** — `gen.py` generates both public (2,000) and hidden (2,000) from the same `GENERATOR_FUNCS` pool with the same seed. The hidden set is just a continuation of the random sequence after the first 2,000. The vocabulary and patterns are identical. (gen.py:421-424, gen.py:369-382)

4. **`no_python` only checks for `.py` file absence + build success** — It does NOT require any correct behaviour. Just deleting Python files and having a compilable Go stub gives 1/6 of the reward. (no_python.py:21-35)

5. **At runtime, the Go binary runs inside the verifier container where `/tests/data/` exists** — `behaviour.py` builds the binary and runs it via `subprocess.run()`. The binary runs in the same filesystem where `hidden_expected.txt` lives. If the binary searches for and reads `/tests/data/hidden_expected.txt`, it gets perfect answers. (behaviour.py:39-71, tests/Dockerfile:9)

## Cheat 1 — Build Trick + Naive Title

**What it does:**  
Creates a minimal Go program that compiles successfully, deletes all `.py` files to pass `no_python`, and implements only a trivial `strings.Fields` + capitalize-first-letter approach. No real titlecase rules are implemented — no small words, no Mac/Mc, no apostrophes, no subphrase handling.

**Expected Score:**  
- `build`: 1.0 (Go compiles)  
- `no_python`: 1.0 (all `.py` files deleted, Go builds)  
- `behaviour`: ~0.1–0.3 (naive capitalization matches some easy titles)  
- **reward**: ~(1 + 1 + 4×0.2) / 6 ≈ **0.47**

**Why it works:**  
`build` and `no_python` are scored independently with no behaviour requirement (reward.toml:4). The naive capitalizer matches titles that are simple "capitalize every word" cases. `build.py` lines 18-28 and `no_python.py` lines 18-37 have no cross-dependency with `behaviour`.

- Or reduce the weight of `build` and `no_python` to near-zero

## Cheat 2 — Read the Exam

**What it does:**  
Creates a Go program that, at runtime, searches the filesystem for hidden answer files (`/tests/data/hidden_expected.txt` and other paths). If found, it reads the file and prints answers line-by-line, achieving perfect or near-perfect `behaviour` score. Also passes `build` and `no_python`.

**Expected Score:**  
- `build`: 1.0
- `no_python`: 1.0
- `behaviour`: **1.0** if answers are reachable, ~0.2 if not
- **reward**: **(1 + 1 + 4×1.0) / 6 = 1.0** if answers are reachable

**Job folder:** *(to be filled after Harbor run)*

**Why it works:**  
`behaviour.py` (lines 59-64) runs the Go binary via `subprocess.run()` in the verifier container. The verifier's `Dockerfile` (line 9) copies all test files to `/tests/`. The Go binary runs in the same container and can access `/tests/data/hidden_expected.txt`. There is no sandboxing or filesystem restriction on the Go binary's read access.

**How to fix:**  
- Run the Go binary in a separate, restricted container with no access to `/tests/`
- Or use `chroot`, namespaces, or a minimal `scratch`-based Docker image to run the binary
- Or verify that the binary doesn't open any files (check `/proc` or use `strace`)
- Or set `environment_mode = "same"` and ensure tests are mounted read-only outside the agent's reach

## Cheat 3 — Half Port (Easy Rules Only)

**What it does:**  
Implements only the simplest titlecase rules: capitalize first letter of each word, keep small words lowercase (unless first/last), handle hyphens and slashes at a basic level. Skips ALL hard rules: Mac/Mc prefixes, apostrophe handling (d'/o'/l'), consonant acronyms, inline periods, UC_ELSEWHERE, subphrase capitalization, SMALL_FIRST regex, etc.

**Expected Score:**  
- `build`: 1.0
- `no_python`: 1.0
- `behaviour`: ~0.5–0.7 (many titles follow simple capitalize-first-letter pattern)
- **reward**: ~(1 + 1 + 4×0.6) / 6 ≈ **0.73**

**Job folder:** *(to be filled after Harbor run)*

**Why it works:**  
The hidden exam is generated from `gen.py` which produces titles from 12 generator functions (gen.py:369-382). Many generators (`gen_normal_title`, `gen_whitespace_cases`) produce titles where simple first-letter capitalization is correct. The 2,000-line hidden exam is too small and insufficiently weird to separate a half-port from a real port. The `behaviour` scoring (behaviour.py:80-86) gives proportional credit — there's no minimum threshold.

**How to fix:**  
- Use a much larger exam (100,000 inputs as recommended in the training doc)
- Include more "weird" edge cases: `Mcx-`, `v1.2`, `_dream`, tabs, non-breaking spaces, `ıstanbul`
- Add a minimum threshold to `behaviour` (e.g., score 0 if match rate < 0.95)
- Use the kit scripts (`make_pool.py`, `answers.py`) to generate a diverse, large pool
